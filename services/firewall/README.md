# Firewall Antizapret: списки и исключения

Firewall работает в сетевом пространстве хоста и фильтрует Docker-трафик
по спискам `az_firewall_v4` / `az_firewall_v6`. Исключения по умолчанию
выключены. Они нужны, например, когда в блоклист попали SMTP-серверы Mail.ru.

## Как работает

- В `DOCKER-USER` каждой семьи добавляется помеченный переход в собственную
  цепочку `AZ-VPN-FILTER`.
- Установленные соединения и совпавшие исключения возвращаются из этой
  цепочки. Остальные источники проверяются по блоклисту.
- `RETURN` означает пропуск проверки Antizapret, а не глобальный `ACCEPT`:
  последующие правила Docker, UFW и других фильтров продолжают действовать.
- Исключение проверяет интерфейс, исходный публичный адрес назначения,
  протокол и исходный порт до DNAT. Поэтому перенаправление портов Docker
  не меняет смысл настройки.
- Оба списка и исключения проверяются до изменения правил. Непустые валидные
  списки сначала загружаются во временные ipset, затем заменяются через
  `ipset swap`. Замена атомарна для каждой семьи; общей транзакции IPv4+IPv6 нет.
- Собственная цепочка обновляется через `iptables-restore --noflush`, без
  очистки таблиц хоста. Неполная загрузка и ошибки проверки сохраняют
  действующие блоклисты; повторная попытка выполняется через 30 секунд.
- При первом запуске без пригодных списков фильтрация ещё не установлена:
  контейнер повторяет загрузку и сообщает об ошибке в журнале.
- При штатной остановке удаляются только помеченные переходы, собственные
  цепочки и ipset. При SIGKILL очистка невозможна.

Старая версия имела непомеченное правило `ESTABLISHED,RELATED ACCEPT`.
Новая версия не удаляет такие общие правила: они могут принадлежать другому
сервису. Точный старый DROP по `az_firewall_v4/v6` удаляется при миграции.
Нельзя одновременно запускать старый и новый firewall на одном хосте:
они используют одинаковые имена ipset.

## Исключения для nl-vps

Файл `exceptions.mail.example` уже содержит TCP 25, 80, 443, 465, 587, 993,
4190 и UDP 443 для публичных адресов nl-vps. Формат строки:

```text
ens3 91.184.253.97 tcp 25,80,443,465,587,993,4190
ens3 2a13:36c0:1ff:1965::10 udp 443
```

Поддерживаются комментарии `#` и пустые строки. Адрес должен быть отдельным
IPv4/IPv6, без CIDR; порты — числа 1–65535 через запятую. Неверный файл
останавливает обновление, не отключая уже установленную фильтрацию.

В environment сервиса задайте:

```yaml
EXCEPTIONS_FILE: /root/exceptions.mail.example
```

В обычном Compose можно установить `FIREWALL_EXCEPTIONS_FILE` в `.env`:
его значение подставляется конфигурацией сервиса. В Swarm используйте
экспортированную переменную либо явное значение в итоговом YAML; `docker
stack deploy` сам `.env` не читает. Для своего файла используйте read-only
bind mount или Swarm config и укажите его путь внутри контейнера.

На других узлах пример не разрешит трафик к их собственным адресам,
но предпочтительно задавать исключения только там, где они нужны.
Изменение файла применяется при следующем обновлении; для немедленного
применения выполните `docker exec <firewall-container> /root/block.sh apply`
при наличии загруженных списков. Вызовы `block.sh` сериализуются через
`flock`, поэтому ручное применение не конфликтует с периодическим обновлением.

## Что пересобрать и как применить вручную

Нужен только образ **firewall**. VPN, Caddy, Stalwart и webmail пересобирать
не требуется. Старый образ `xtrime/antizapret-vpn-firewall:6.4.0` не содержит
этих изменений. Из корня репозитория:

```sh
docker build -t nmisha/antizapret-vpn-firewall:6.4.0-mail1 services/firewall
docker push nmisha/antizapret-vpn-firewall:6.4.0-mail1
```

Используйте свой доступный registry/тег. Для узлов разных архитектур:

```sh
docker buildx build --platform linux/amd64,linux/arm64 \
  -t nmisha/antizapret-vpn-firewall:6.4.0-mail1 --push services/firewall
```

В вашей конфигурации развёртывания замените `services.firewall.image` новым
тегом и добавьте `EXCEPTIONS_FILE`. Убедитесь, что итоговый Compose/Swarm YAML
содержит оба значения. В Swarm настройте `deploy.update_config.order: stop-first`,
чтобы две версии не работали одновременно. Затем выполните привычное
развёртывание стека. Swarm не собирает образ по секции `build`.

В этом репозитории CI задаёт `xtrime/...` и соответствующие credentials;
он не является настроенной публикацией в namespace `nmisha`.
Приведённые команды предназначены для ручной сборки и публикации.

## Переход с отдельного почтового скрипта

1. До обновления сохраните `iptables-save` и `ip6tables-save`. Оставьте
   действующий `mail-smtp-firewall.service` включённым на время миграции.
2. Разверните новый firewall с исключениями и проверьте журнал и правила:

   ```sh
   iptables -S DOCKER-USER
   iptables -S AZ-VPN-FILTER
   ip6tables -S DOCKER-USER
   ip6tables -S AZ-VPN-FILTER
   ```

3. Отдельно проверьте разрешения UFW/INPUT для нужных портов IPv4 и IPv6.
   На nl-vps Docker-сеть почты только IPv4; IPv6 принимает `docker-proxy`,
   его трафик проходит через INPUT, а не DOCKER-USER. Данный firewall
   намеренно не меняет INPUT и не заменяет разрешения UFW.
4. После проверки отключите прежние исключения:

   ```sh
   cd /root/mail
   sudo sh allow-smtp.sh disable
   ```

5. Повторно проверьте HTTPS, SMTP с внешнего адреса из блоклиста, доставку
   письма и доступ по IPv6. Для отката сначала включите почтовый скрипт
   обратно, затем возвращайте прежний образ firewall.

Исключения не создают listener 587, не выпускают сертификаты и не добавляют
AAAA-записи. Эти настройки остаются отдельными задачами почтового сервера.
