## Окружение

Локальная Lima/VZ VM, Ubuntu 24.04, Linux 6.8.0-147-generic, Docker 29.1.3,
TAYGA 0.9.2-8 из Ubuntu. Jool был установлен в этой тестовой VM ранее,
но его модули выгружены; runner отказывается работать с загруженным jool_siit.
Swarm одноузловой; конечный IPv6-сервер контролируемый, внутри стенда.
Образы antizapret и AdGuard собраны локально в Docker Desktop.

## Проверено

- Полная сборка antizapret, включая Go tests и 91 Python-тест.
- Сборка AdGuard с routes из нового antizapret-образа.
- Обычный Compose/Swarm без NAT46 и дополнительный override: преобразование
  через compose2swarm, проверка `docker stack config`, сохранение overlay,
  forwarding sysctls и правильное включение/выключение NAT46.
- TUN создаётся в задаче Swarm с NET_ADMIN/MKNOD без privileged/device mount.
- Пакетные тесты через production `nat46-control.py` и `DNAT6Backend`.
- Два IPv4-клиента с одинаковым исходным портом 40000: TCP и UDP/443.
- Добавление назначения DNAT6 сохраняет открытое TCP-соединение и PID TAYGA.
  Динамической перезагрузки TAYGA нет.
- ICMP echo; при IPv6 MTU 1280 малый пакет проходит, DF payload 1320
  возвращает IPv4 fragmentation-needed с MTU 1260.
- Неизвестный synthetic-адрес отбрасывается один раз без петли через TUN.
- IPv4 DNAT продолжает работать наряду с TAYGA.
- Два настоящих QUIC/443 клиента передают и получают обратно по 73728 байт.
- `dnsmap`: частичный CNAME → дополнительный AAAA → synthetic A → IPv6 TCP.
- Общий checkpoint `nat46-state-v1` содержит IPv4 и IPv6 назначения. После
  SIGKILL DNS, очистки таблиц и повторного production startup оба семейства
  сохраняют synthetic IP. Следующее назначение получает свободный адрес.
- При ошибке checkpoint DNS не публикует новый адрес; он не возвращается в
  свободный пул при неопределённом состоянии правил.
- Реальный AdGuard: внутренние AAAA разрешены, обычные AAAA подавлены;
  A-запросы, выбор выхода и блокировки сохранены; повторное включение не
  дублирует правило, выключение возвращает глобальный запрет AAAA.
- Полный production `/init.sh`: обычный режим и NAT46 запускаются/останавливаются
  по SIGTERM; смерть TAYGA завершает PID1 с ошибкой.
- Production host-helper: настройка dummy/macvlan и config-only сети,
  повторный apply без дублирования hooks/NAT, отказ при несовместимом IPAM
  и попытке отключить host NAT66 без routed public prefix.

Host не содержит маршрута клиентского технического /96: только локальный
/64 интерфейсов контейнеров. В стенде внешний интерфейс ноды эмулирует
отдельная IPv6-сеть с сервером. В режиме без внешнего NAT66 используется
явный обратный маршрут тестового /64; это проверка маршрутизации, а не
проверка выделенного провайдером публичного префикса.

## Особенности, учтённые в коде

В Swarm `/proc/sys` read-only. Запись sysctl внутри задачи напечатала новое
значение и вернула exit code 0, но forwarding фактически оставался 0.
Он задаётся при создании сервиса; контроллер проверяет `/proc/sys`.

Сохранение только IPv6 оставляло риск повторной выдачи адресов потерянных
IPv4 mappings после аварии. Поэтому NAT46 использует один атомарный снимок
обоих семейств перед DNS-ответом. Старые файлы Jool без заголовка версии
не импортируются автоматически. При выключенном NAT46 обычный механизм
IPv4 mappings сохраняется.

## Что ещё не проверено

Реальные VPN-туннели, межузловой Swarm, host reboot и порядок восстановления
задач, публичный IPv6 провайдера, производительность и произвольные варианты
фрагментации. QUIC-тест — stream echo, а не браузерный HTTP/3.
Отключение host NAT66 не отключает MASQUERADE контейнера и не проверяет выдачу
отдельного публичного IPv6 каждому VPN-клиенту. WARP вместе с NAT46 запрещён.
