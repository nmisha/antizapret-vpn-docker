# Результат эксперимента — 2026-11-06

Основа ветки: 57c12e4ccb6c2b2e2b7b1a88e3796c4a35c0067e.
Production-код и настройки серверов в этом эксперименте не менялись.

## Окружение

Локальная Lima/VZ VM, Ubuntu 24.04, Linux 6.8.0-147-generic, Docker 29.1.3.
Пакет TAYGA 0.9.2-8 из Ubuntu. Jool был ранее установлен в этой тестовой VM,
но его модули выгружены; runner отказывается работать с загруженным jool_siit.
Swarm — одноузловой; конечный IPv6-сервер контролируемый, внутри стенда.

## Проверено

- TUN создаётся в задаче Swarm с NET_ADMIN/MKNOD без privileged/device mount.
- Статический алгоритмический префикс TAYGA + динамические правила DNAT6.
- Два IPv4-клиента с одинаковым исходным портом 40000: TCP и UDP/443.
- Добавление второго назначения DNAT6 сохраняет открытое TCP-соединение.
  PID TAYGA не меняется, SIGHUP не посылается.
- ICMP echo проходит; при IPv6 MTU 1280 малый пакет проходит, DF payload 1320
  возвращает IPv4 fragmentation-needed с MTU 1260.
- Неизвестный synthetic-адрес отбрасывается один раз, без петли через TUN.
- IPv4 DNAT продолжает работать: bridge-тест направляет его на IPv4 сервера,
  Swarm-тест — на IPv4 gateway хоста.
- Два настоящих QUIC/443 клиента передают и получают обратно по 73728 байт.
- Те же основные пакетные проверки проходят в Swarm без внешнего host NAT66,
  при явном маршруте ULA-префикса контейнеров от тестового сервера.

Host не содержит маршрута клиентского технического /96. Он маршрутизирует
только дополнительную ULA-сеть интерфейсов контейнеров. В обычном режиме
host NAT66 заменяет ULA-источник публичным IPv6 ноды. В стенде этот внешний
интерфейс эмулирует отдельная IPv6-сеть с сервером.

## Найденная особенность Swarm

Запись net.ipv6.conf.all.forwarding изнутри задачи не работала: /proc/sys был
read-only. sysctl вернул exit code 0 и напечатал запрошенное значение, но
реальное осталось 0. Передача sysctls при создании сервиса исправила путь.
Runner проверяет /proc/sys, а не только результат команды записи.

## Что ещё не проверено

DNS-интеграция, persistence/recovery mappings, реальные VPN-туннели,
межузловой Swarm, reboot/порядок запуска, публичный IPv6 провайдера,
производительность и произвольные варианты фрагментации. QUIC-тест — stream
 echo, а не браузерный HTTP/3. Отключение host NAT66 не отключает NAT66 внутри
контейнера и не проверяет выдачу отдельного публичного IPv6 каждому клиенту.

## Вывод

Схема жизнеспособна на уровне пакетов и упрощает зависимости и управление:
нет Jool/DKMS, EAMT, reload mappings в TAYGA и маршрута клиентского /96 на host.
IPv6-канал namespace контейнера к host остаётся необходим. Текущий прототип
сохраняет дополнительный macvlan/shim и NAT66; это не production-интеграция.

Подробные временные логи: tmp/tayga-experiment/bridge.log,
swarm-final.log и swarm-routed.log. Воспроизведение — README.md рядом.
