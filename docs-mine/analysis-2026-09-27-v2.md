## 1. Что стало лучше upstream

1. **API** (`services/antizapret/api/main.go`). Upstream: постоянный grep с разделителем `__DELIM__` и двойной `RLock` →
   возможные вечные зависания и урезанные списки с кодом 200. Сейчас: один `grep -a -v -E` на запрос, конец данных —
   закрытие stdin; ошибка после начала ответа рвёт соединение (AdGuard оставляет прежний список); отсутствующий фильтр →
   503; файлы исключений не правятся на месте. Замер (300 тыс. строк, ~420 шаблонов): прежняя реализация с постоянным grep (2eb3ea3, по устройству как upstream) ~0,31 с, сейчас ~0,075 с.
2. **Обработка списков**: staging-каталог, `pipefail`, `flock` вместо «файла-существования», маркеры `.ready`
   различают «пустой после успешной загрузки» и «не скачан»; частичный сбой загрузки не портит кэш.
3. **Исключения** (`parse.sh`): пустая строка в `exclude-ips*-custom.txt` больше не обнуляет список (в upstream обнуляет);
   `10.0.0.0/8` больше не исключает `110.0.0.0/8`; регулярки по-прежнему работают.
4. **Невалидные строки** (IPv6, опечатки) пропускаются с предупреждением. В upstream такая строка попадала в OpenVPN-маршруты
   как мусор, в промежуточной версии форка — блокировала все списки.
5. **ASN-списки**: `sanitize-lists.awk` больше не обрезает строку до первого слова (`Google LLC`, `/cloud flare/`) —
   ошибка была и в upstream, на regex с пробелом dnsmap падал.
6. **dnsmap**: применение правил iptables в отдельном потоке с таймаутом, падение воркера не вешает DNS-запросы.
7. **routes**: сверка с реальной таблицей ядра (восстанавливает маршруты, удалённые извне), некорректная строка не отбрасывает
   весь список, ошибка одного маршрута не останавливает остальные, IP-списки не фильтруются доменными regex.
8. **AdGuard**: раздельные checksum local/world, refresh последовательно, сбой refresh не валит DNS, 401 не уводит
   в рестарт-луп, `curl -u` вместо base64 с переносом, пустой хеш пароля не затирает рабочий логин.
   `cache_optimistic: false` — не раздаются протухшие fake-IP.
9. **VPN-серверы** (wireguard, openvpn, ocserv): цепочка `az_clients` — клиент ходит только по выданным маршрутам;
   запрет ping через туннель.
10. **WireGuard**: пустой `WG_HOST` (таймаут определения IP) больше не затирает Endpoint в БД.
11. **firewall**: переписан на Python — валидация обоих списков до изменения правил, атомарный `ipset swap`,
    только собственная цепочка и помеченные хуки.
12. **Тесты**: +~1300 строк тестов (list-cache, dnsmap, routes, api, adguard failover, https generator, firewall).

## 2. Что хуже upstream или рискованно (внесено форком)

### 2.1 Маршруты VPN-контейнеров работают на чужом бинарнике — высокая
`COPY --from=xtrime/antizapret-vpn:6.9.1 /usr/bin/routes` в Dockerfile adguard, wireguard, openvpn, proxy.
Код списков в `routes` выполняется только с `--vpn` (wireguard, openvpn, ocserv, proxy), поэтому улучшения для списков
(пропуск строк, продолжение после ошибки, `filter_custom=0`) и сверка с ядром внутри VPN-контейнеров и adguard
**сейчас не работают**. В az-local свой `routes` (без `--vpn`) — там действует только сверка маршрутов основной таблицы. Решение: копировать из собственного
`nmisha/antizapret-vpn:<версия>`, собранного после правок. *Вы запланировали.*

### 2.2 Dashboard без авторизации, всё за Authelia — средняя
- basic auth в `dashboard/files/init.sh` снята (`create_empty_auth`), неиспользуемая `disable_auth()` осталась;
- все `PROXY_SERVICE_N` за `forward_auth authelia:9091` — без Authelia (её нет в базовом compose) все UI дают ошибку;
- VPN-клиентам разрешён `DOCKER_SUBNET`, поэтому `http://dashboard.antizapret` открывается из VPN **без авторизации**
  (раскрывает список сервисов и внутренние адреса);
- `HTTP PROXY LOCAL/WORLD` (8143/8243) в дефолтном compose за `forward_auth` — прокси-клиенты не проходят редирект Authelia.

### 2.3 AdGuardHome.yaml — средняя
- **«Block Porno for Local/World»** (`allow=0`) ничего не блокирует для пользователей: правила вида
  `||x^$dnsrewrite=SERVFAIL,client=az-local` отвечают SERVFAIL только выходам. Итог по коду:
  - az-local: SERVFAIL → CoreDNS идёт дальше → в итоге настоящий IP, сайт открывается напрямую;
  - az-world: SERVFAIL → dnsmap переспрашивает `az-resolver` → если IP в ASN из `asn-world.txt` (Cloudflare, Akamai,
    Amazon…) — **маршрутизируется через world**, потому что эти списки к `az-resolver` не подключены.
  Если цель — блокировать: нужен глобальный список без `client=` (`allow=0&suffix=0`). Если цель — не пускать через VPN:
  домены должны попасть и в правила `az-resolver` (как `exclude-hosts-custom.txt`).
  То же для добавленных в `exclude-hosts-dist.txt` `xvideos`, `xnxx`…: dist-исключения к `az-resolver` не применяются.
  *Вывод по коду, на живом стенде не проверялся.*
- `upstream_timeout: 10s` (upstream `1s`): учитывает failover CoreDNS (до ~7 с при недоступном world), но клиентские
  резолверы часто ждут меньше (Windows ~1–2 с на попытку, glibc 5 с) — будут повторы. Приемлемо, но держать в уме.
- В репозитории (форк на GitHub) закоммичены `rewrites` с картой домашней сети (`*.mi`, `*.di`, внутренние IP)
  и публичный IP VPS. Шаблон копируется только при первом запуске (`cp -n`), поэтому это можно держать в серверном
  конфиге, а не в образе.

### 2.4 Дефолтные секреты в compose — средняя
- tgbot/dns-guard: `change-me-*` токены и `password` в compose; пустой токен = API без авторизации
  (`if token != "" && …`).
- Grafana: `GF_SECURITY_ADMIN_PASSWORD` с дефолтным значением.

### 2.5 Гигиена и сопровождение — низкая
- Мусор: `main_my.go.bak`, `AdGuardHome.yaml.bak`, `index.html.bak`, `init.sh.bak`, `init_my_old*.sh`,
  закоммиченный `__pycache__/*.pyc`, `sr_ch_rights-old.sh`, `docs-mine/… copy.txt`, `docs-mine/1`.
- `gofmt` в tgbot/dns-guard (4 файла).
- CI (`build.yml`) работает только для `v6`/`dev` — `v6-mine` не собирается и не тестируется.
- `https/tests/test_generator.py` использует образ `6.7.9-3`, compose — `6.7.9-5` (тесты проверяют скрипты, не сам образ).
- `sr_update_all.sh` — `docker system prune -af` (чистит весь хост), `sr_git_pull.sh` — `git reset --hard`.
- `sr_swarm_start.sh` — отрендеренный compose со всеми паролями уходит в `docker run --pull always xtrime/antizapret-vpn:6`.
- `ADGUARDHOME_PASSWORD_HASH` в compose не нужен при заданном пароле (добавлен под сценарий README).

## 4. Мерж `upstream/dev` — что учесть

> **Выполнено** в локальной ветке `merge/upstream-dev` (merge-коммит `b261b6f` поверх `v6-mine` + `fb4da29`
> с исправлением healthcheck CoreDNS). Всё состояние всех сервисов — в `/dev/shm`; `doall.sh` — `flock` на
> `/dev/shm/.doall_lock` (тот же блок, что в PR №6); AdGuard — раздельные checksum в `/dev/shm`; теги образов
> `nmisha/*:<версия upstream>-1`. Тесты: antizapret 66, `tests/` 11, firewall 3 — OK. Ниже — исходный разбор.

Upstream/dev (e3dd87d) переносит flag/lock/md5-файлы в `/dev/shm` (очищается при рестарте). Пробное слияние:

- **Конфликты (9)**: adguard `docker-compose.yml`, `entrypoint.sh`, `healthcheck.sh`; antizapret `docker-compose.yml`,
  `init.sh`, `doall.sh`; `ocserv/compose.yml`, `openvpn/docker-compose.yml`, `wireguard/docker-compose.base.yml`.
- **Опасные автослияния**: `antizapret/healthcheck.sh` и `dnsmap.py` сольются без конфликта и начнут читать
  `/dev/shm/.config_md5` и `/dev/shm/.dns_started`. Если конфликт в `init.sh` разрешить в пользу своей версии
  (пишет `/.config_md5`), healthcheck будет видеть пустой старый md5 и **запускать doall каждые 10 с**.
  Правило: выбрать одну схему для всех файлов сервиса. При переходе на `/dev/shm` сохранить `flock` в doall
  (upstream оставляет цикл `while [ -f lock ]`), раздельные `/.config_md5.local|world` в AdGuard и ваши улучшения
  healthcheck.
- wireguard, ocserv, openvpn: init и healthcheck сливаются автоматически и согласованно (оба на `/dev/shm`).
