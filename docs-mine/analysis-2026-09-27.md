## Часть 1. Регрессии относительно upstream (было правильно → стало хуже)

### R1. AdGuard и CoreDNS потеряли самовосстановление
`services/adguard/docker-compose.yml`, `services/coredns/docker-compose.yml`

upstream:
```yaml
test: (timeout 10m /root/healthcheck.sh || kill -TERM 1) 2>&1 | tee /proc/1/fd/1
```
у вас:
```yaml
test: ["CMD", "/root/healthcheck.sh"]
```

- В обычном `docker compose` статус `unhealthy` **не перезапускает контейнер**. Upstream специально убивал PID 1,
  чтобы сработал `restart: unless-stopped`. Теперь зависший AdGuard или CoreDNS так и останется висеть.
  В swarm это не проявится: там unhealthy-задача пересоздаётся.
- Вывод healthcheck больше не попадает в `docker logs` (раньше шёл `tee /proc/1/fd/1`).
- В остальных сервисах (wireguard, openvpn) шаблон upstream сохранён, так что поведение теперь разное.

Что сделать: вернуть `|| kill -TERM 1` и `tee`, оставив ваши `retries`/`start_period`. Если убийство PID 1 убрано
намеренно (чтобы не было рестарт-лупа при недоступном az-world), нужно явно разделить «liveness» (DNS/API живы)
и «maintenance» (обновление фильтров) — в вашем healthcheck это уже частично сделано.

### R2. CoreDNS: `max_fails 0` → `max_fails 1` + `health_check 1s`
`services/coredns/Corefile.template`

- upstream: `max_fails 0` — строгий sequential failover, выход никогда не помечается «мёртвым».
- у вас: один проваленный health-probe (`. IN NS`, таймаут, потерянный UDP-пакет) выводит az-world из ротации.
  Тогда world-домены резолвятся через az-local, получают fake-IP из диапазона local, и трафик идёт **не через тот выход**.
  Для пользователя это выглядит как «иногда сайт не открывается».
- Probe идёт через dnsmap → DoH AdGuard → upstream-резолверы. Если AdGuard медленный, flapping вероятен.
- Каждую секунду по probe на каждый выход → лишний шум в логах dnsmap (`log request,reply` + `print`)
  при лимите логов 1 МБ × 3.

Коммит 0ac29e1 («Keep local DNS available when the world exit is unreachable») — осознанный компромисс.
Имеет смысл: увеличить `max_fails` (3–5), задать `health_check 5s`, проверить на практике, что при кратковременной
потере world нет переключения.

### R3. parse.sh стал «всё или ничего» для одной кривой строки
`services/antizapret/root/antizapret/parse.sh` (цикл sipcalc)

- upstream: IPv6-строка или мусор давали сломанную строку `push "route ..."` в `openvpn-blocked-ranges.txt`,
  но остальные списки обновлялись.
- у вас: `Invalid route mask` → `exit 1` → doall `exit 2` → **ни один список не обновляется**, пока строку не удалят.
  В логах это видно только в выводе healthcheck.
- То же в `routes.go`: `validRouteList` отбрасывает весь список из-за одной строки, а `applyAZRoutes` прекращает
  цикл на первой ошибке `replaceRoute` (последнее было и в upstream).

Что сделать: пропускать и логировать некорректную строку (или отфильтровывать IPv6 ещё на этапе sanitize),
а не прерывать публикацию.

### R4. Dashboard без авторизации, https завязан на Authelia
`services/dashboard/files/init.sh` (`create_auth` → `create_empty_auth`), `services/https/files/init.sh` (`forward_auth`)

- upstream: dashboard закрыт lighttpd basic auth; Caddy проксировал сервисы без `forward_auth`,
  у каждого сервиса своя авторизация.
- у вас: basic auth снята, все `PROXY_SERVICE_N` за `forward_auth authelia:9091`.
  - Через Caddy всё закрыто Authelia (fail-closed: без Authelia — ошибки у всех UI). Для вашей установки
    (authelia в `docker-compose.override.yml`) это корректно. Но базовый `services/https` без Authelia неработоспособен.
  - **Прямой доступ из VPN** (`http://dashboard.antizapret:80`, по IP docker-подсети) теперь без авторизации:
    `az_clients` в wireguard/openvpn явно разрешает `DOCKER_SUBNET`. Dashboard рассчитан на такой режим
    (`internalHostname === currentHost`).
  - `HTTP PROXY LOCAL/WORLD` (8143/8243) за `forward_auth`: прокси-клиенты не умеют проходить редирект Authelia.
    В вашем override этих сервисов нет, но в дефолтном compose они есть.
- Неиспользуемая функция `disable_auth()` осталась в dashboard/init.sh.

### R5. AdGuard healthcheck стал падать на ответ 401
`services/adguard/healthcheck.sh`

- upstream: `curl -s` без `-f` → при 401 скрипт продолжал работу.
- у вас: `CLIENTS=$(curl -fsS ...)` при `set -e` — присваивание возвращает код `curl`, скрипт завершается с 1.
  Если healthcheck не знает пароля (задан только `ADGUARDHOME_PASSWORD_HASH`, как предлагает README), контейнер
  навсегда unhealthy, а в swarm уходит в рестарт-луп. Одновременно перестают обновляться фильтры и IP клиентов.
- Проверка `[[ "$CLIENTS" == 404* ]]` при `-f` никогда не сработает — мёртвый код.
- `base64` в busybox переносит строку после 76 символов → длинные логин+пароль ломают заголовок. Нужен `base64 -w0`.
- Если не задан ни пароль, ни хеш, entrypoint пишет пустой хеш → вход в AdGuard невозможен.

## Часть 2. Что в вашем diff сделано лучше upstream (оставить)

- **API** (`api/main.go`): upstream брал `RLock` дважды (внешний + внутренний) — рекурсивный RLock в Go при ожидающем
  писателе даёт deadlock. У вас исправлено. Запись в stdin grep вынесена в горутину — нет взаимной блокировки пайпов.
- **dnsmap.py**: применение пачек iptables вынесено в отдельный поток, добавлен timeout на `iptables-restore`,
  при падении воркера DNS-запросы не зависают.
- **doall.sh**: `flock` вместо «файла-существования» — нет гонок и вечной блокировки после kill -9.
- **download.sh / parse.sh**: staging-каталог, `pipefail`, списки независимы, частичная ошибка не портит кэш,
  маркеры `.ready` различают «пустой после успешной загрузки» и «не скачан».
- **routes.go**: сверка с реальными таблицами ядра — восстанавливает маршруты, удалённые извне.
- **AdGuard healthcheck**: раздельные checksum для local/world, refresh последовательно, сбой refresh не валит DNS.
- **CoreDNS config.sh**: не пишет фиктивные `169.254.x.x`, атомарная замена Corefile.
- **wireguard/openvpn/ocserv**: серверная цепочка `az_clients` (клиент не может использовать сервер как exit
  через ручные маршруты), запрет ping через туннель.
- **firewall**: переписан на Python — валидация до применения, атомарный swap ipset, не трогает чужие правила.

## Часть 3. Ошибки, общие с upstream или в вашем коде

### 1. Пустая строка в `exclude-ips*-custom.txt` обнуляет список
`parse.sh`: `grep -v -E -f exclude-…`. Пустая строка = шаблон, совпадающий со всем → `-v` выкидывает всё;
код 1 трактуется как «валидный пустой результат» → пустой `ips.txt` без ошибки. Проверено:
`printf '10.0.0.0/8\n\n' > ex; grep -v -E -f ex in` → пусто.
Второе: регулярки на подстроку — `10.0.0.0/8` исключает и `110.0.0.0/8`.
**Исправить**: прогонять exclude-файлы через `sanitize-lists.awk`, для IP использовать `-F -x`.

### 2. API: вечное зависание из-за `__DELIM__`
`api/main.go` `RegexFilter.Filter`. Если regex из `exclude-hosts-custom.txt` совпадает с `__DELIM__`
(`[A-Z]`, `_`, `.*`, `\w`), grep его выбрасывает, `scanner.Scan()` ждёт вечно с удержанием блокировок →
`/update/` и все `/list/` висят. Проверено: `echo __DELIM__ | grep -v -E '[A-Z]'` → пусто.
Текущий `exclude-hosts-dist.txt` безопасен.
**Исправить**: перейти на Go `regexp` (RE2 покрывает ERE, кроме backreference) без внешнего процесса.

### 3. API: частичный список с кодом 200
`processBuffer` при ошибке фильтра делает `return` после отправленного 200 → AdGuard получает урезанный список.
Сломанный `RegexFilter` (grep убит) остаётся глобальным до следующего `/update/`.
`http.Error` после `WriteHeader` не меняет статус.

### 4. tgbot, dns-guard собираются только под amd64
`services-mine/tgbot/Dockerfile:17`, `services-mine/dns-guard/Dockerfile:10`: `GOARCH=amd64`, при этом `x-bake`
собирает `linux/arm64` → `exec format error`. **Исправить**: `ARG TARGETARCH` + `GOARCH=$TARGETARCH`.

### 5. Чужой бинарник `routes` в VPN-контейнерах
`COPY --from=xtrime/antizapret-vpn:6.9.1 /usr/bin/routes` в adguard, wireguard, openvpn, proxy.
Ваши правки routes.go (5e94b2e и др.) есть только в az-local. **Исправить**: копировать из `nmisha/antizapret-vpn:<версия>`
или собирать `routes` отдельной стадией.

### 6. WireGuard: пустой host в БД
`services/wireguard/init.sh:7`: `timeout 1s curl icanhazip.com`. При таймауте `update_db` пишет `host=''`
(строка 168) при каждом старте → новые профили без Endpoint. **Исправить**: не обновлять `host`, если пусто;
таймаут 5–10 с.

### 7. doall из healthcheck каждые 10 с после сбоя
`services/antizapret/healthcheck.sh:50-58`: при ошибке doall с живым кэшем md5 не обновляется → каждая проверка
снова запускает doall (до 5 мин) и заново качает списки. Кроме того, md5 в init.sh считается **до** стартового doall,
поэтому первый healthcheck всегда делает второй doall.

### 8. Маршруты фильтруются исключениями доменов
`routes.go:24-25`: `…/list/?raw=1&file=…ips.txt` без `filter_custom=0` → IP-список прогоняется через
`exclude-hosts-custom.txt`. Плюс зависимость от API из п.2.

### 9. dnsmap: mappings не истекают
`dnsmap.py`: цепочка `dnsmap` только растёт (линейная проверка на каждое новое соединение). При исчерпании /15
`reset_mappings` сразу переиспользует fake-IP → клиенты с кэшем DNS попадают на чужой хост.
Латентный баг: при дубликате real_addr (`add_mapping`, стр. ~317) fake_addr не убирается из свободных → возможны два
DNAT на один адрес.

### 10. dnsmap только UDP
`init.sh:191` без `--tcp`: усечённый ответ (TC) → повтор по TCP в никуда. Проверить на доменах с большим числом A-записей.

### 11. API без авторизации + SSRF
`/list/?raw=1&url=…` проксирует GET на любой адрес, `/doall/` запускает обновление. VPN-клиентам разрешён
`DOCKER_SUBNET` → API az-local:80 достижим из VPN. Ограничить iptables или токеном.

### 12. Секреты уходят в сторонний образ
`sr_swarm_start.sh`: отрендеренный compose со всеми паролями → `docker run --pull always xtrime/antizapret-vpn:6 compose2swarm`
(всегда latest, с сетью). Использовать свой собранный `compose2swarm`, хотя бы `--network none`.
Там же исправить сериализацию `size` вместо обхода через `sed`.

### 13. Опасные скрипты обслуживания
- `sr_update_all.sh`: `docker system prune -af` — удаляет всё неиспользуемое на хосте, не только этот проект.
- `sr_git_pull.sh`: `git reset --hard` — теряются локальные правки отслеживаемых файлов.

### 14. Токены: пусто = без авторизации
tgbot `risk_notifications.go`, dns-guard `api.go`: `if token != "" && …` → при пустом токене доступ открыт.
В compose закоммичены `change-me-*`, `password`. Не запускаться с пустым/дефолтным токеном,
сравнивать через `subtle.ConstantTimeCompare`.

### 15. Прочее (низкий приоритет)
- `adguard/adguardhome:latest`, `coredns/coredns:latest` — незакреплённые версии.
- `while true; do /opt/api/app; done` и цикл iperf3 без `sleep` (init.sh:187) — 100% CPU при мгновенном падении.
- WireGuard: compose передаёт `WG_MTU`, init.sh читает `MTU` (сейчас совпадает по умолчанию).
- Миграция `wg0.json`: пустой `WG_PERSISTENT_KEEPALIVE` → SQL `,,`, вставка клиентов падает, файл всё равно
  переименовывается в `.backup`.
- Caddy снимает `X-Frame-Options`.
- `services/openvpn/files/checkpsw.sh` пустой (0 байт). Сейчас не подключён, но при включении проверки паролей
  в openvpn-ui примет любой пароль.
- `NewRegexFilter` меняет пользовательские файлы (`sed -i`, `gawk -i inplace`) → меняется md5 → лишний doall.
- CI (`build.yml`) запускается только для `v6`/`dev` — `v6-mine` не собирается и не тестируется.
- Мусор: `*.bak`, `init_my_old*.sh`, `main_my.go.bak`, закоммиченный `__pycache__/*.pyc`,
  `sr_ch_rights-old.sh`, `docs-mine/… copy.txt`, `docker stack rm antizapret antizapret`.
