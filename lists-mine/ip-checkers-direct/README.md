# ip-checkers-direct

Правила, которые выводят IP-чекеры (icanhazip, ipify, ipinfo, ifconfig.* и т. д.) из VPN-туннеля. Клиент ходит к ним напрямую и видит свой настоящий IP, а не IP выхода VPN.

Источник доменов: [../ip_checkers.txt](../ip_checkers.txt) (234 домена).

## Зачем

Маршрутизация в AntiZapret идёт через DNS: в туннель попадает только то, что AdGuard подменил на внутренний адрес `dnsmap`. Домен уходит в туннель по одной из двух причин:

1. Он есть в include-списках (`include-hosts-*`, antifilter, blockedin).
2. Его IP входит в ASN из [../../lists/asn-world.txt](../../lists/asn-world.txt) (Cloudflare, Amazon, Hetzner, OVH, Akamai и др.). Тогда `dnsmap` подменяет весь ответ.

Многие чекеры стоят за Cloudflare, Amazon или Hetzner, поэтому показывали IP выхода VPN. Эти правила исключают их из обоих механизмов.

## Что в папке

| Файл | Что это |
|---|---|
| `gen.py` | Генератор. Читает `../ip_checkers.txt` и `../include-hosts-dist.txt`. |
| `exclude-hosts-custom.txt` | Регулярки ERE. Останавливают ASN-маршрутизацию и фильтруют include-списки. |
| `adguard-custom-rules.txt` | Правила `@@…$dnsrewrite` для доменов, которые всё ещё совпадают с include-записями. |

Оба `.txt` создаются скриптом. Вручную их не правят.

## Как применить

1. **Отключить блокировку.** Если `ip_checkers.txt` подключён в AdGuard как блоклист, отключите подписку. Иначе домены резолвятся в `0.0.0.0`.
2. **Исключения из ASN.** Добавьте содержимое `exclude-hosts-custom.txt` в `config/antizapret/custom/exclude-hosts-custom.txt` (в конец существующего файла). Контейнеры сами подхватят изменение через 5-10 секунд.
   Файл в [entrypoint.sh](../../services/adguard/entrypoint.sh) загружается в AdGuard как блокирующее rewrite для клиента `az-resolver`. Из-за этого `dnsmap` не может проверить ASN и оставляет домен на прямом маршруте.
3. **Исключения из include-списков.** Вставьте `adguard-custom-rules.txt` в AdGuard Home → Filters → Custom filtering rules (http://adguard.antizapret:3000/#custom_rules).
   Нужно для 6 доменов, которые попадают под суффиксные include-записи: `2ip.ua` (`ua`), `ip.me`, `ip.hetzner.com` (`hetzner.com`) и три radar-эндпоинта Cloudflare (`cloudflare.com`). Регулярка из шага 2 суффиксную запись из списка не убирает, поэтому нужны отдельные `@@`-правила.

## Как проверить

С клиента VPN:

```sh
dig icanhazip.com          # публичный IP, а не адрес из диапазона dnsmap
curl https://icanhazip.com # ваш обычный IP, не IP выхода VPN
```

Для диагностики смотрите лог `dnsmap`: он пишет IP, ASN и сработавшее правило для каждого домена.

## Как обновлять

После изменения `../ip_checkers.txt` (или `../include-hosts-dist.txt`) запустите:

```sh
python3 gen.py
```

и снова вставьте результат в те же места. Дубли в `exclude-hosts-custom.txt` лучше удалить, прежде чем добавлять новую версию.

## Как работает разбор

- **Точные домены.** 10 доменов из блока `# /^host$/` в `ip_checkers.txt` (checkip.amazonaws.com, checkip.dyndns.org и др.) записываются как `^host$`. Так исключение не затрагивает весь `amazonaws.com` и его поддомены.
- **Остальные 224 домена** записываются как `(^|\.)host$` и покрывают поддомены. Это то же поведение, что у `||host^` в AdGuard.
- **`@@`-правила** создаются только для доменов, которые совпадают с записью из `include-hosts-dist.txt` (по суффиксу).

## Ограничения

- Приложения со встроенным DoH (браузеры, Android Private DNS) обходят AdGuard, и правила для них не работают.
- Подключения по IP без DNS этими правилами не затрагиваются: DNS-маршрутизация их не видит.
- Часть доменов могла быть в include-списках из-за блокировок в РФ (например, `ip.hetzner.com`, `ip.me`). Если какой-то чекер должен идти через VPN, удалите его из исключений и перегенерируйте.
- Работу `@@…$dnsrewrite` вместе с ASN-маршрутизацией я не проверял. Смотрите лог `dnsmap` на этих 6 доменах.
- Файлы подменяют только маршрут. Чекеры показывают то, что видят: ваш реальный IP, а не заданный вручную.
